## Использованные существующие операции

Только существующий RPC `shiftly_write` через `accountWrite` (идемпотентность по ключу UUID, владелец — auth.uid() на сервере):
- `shift_create` — создание planned-смены с полным набором времени (локальные поля + UTC-мгновения);
- `shift_edit` — изменение места/даты/времени/комментария с expected_revision; revenue/tips не передаются, хранимые значения сохраняются;
- `shift_start`, `shift_complete`, `shift_cancel` — утверждённая машина статусов (planned → in_progress → completed; отмена из planned/in_progress/pending);
- `shift_delete` — мягкое удаление в корзину (30 дней хранения на стороне БД).
Прямых записей из браузера нет; user_id клиент не передаёт; service_role не используется.

## Как сохраняются и загружаются смены

- Чтение: getAccountShifts (requireSupabaseAuth + Auth getUser) → shifts владельца без корзины, время обрезано до HH:mm.
- Запись: форма → accountWrite (валидация на границе) → shiftly_write → инвалидация кэша ["account", userId] → данные перечитываются из Supabase без перезагрузки.
- Время: дата/время интерпретируются в часовом поясе рабочего места; переход через полночь переносит local_end_date на следующие сутки; starts_at/ends_at вычисляются как UTC-мгновения.
- Пересечения: предварительная проверка на клиенте по UTC-мгновениям всех активных смен (включая другие места и ночные смены); при конфликте показывается конфликтующая смена и сохранение блокируется; БД дополнительно отклоняет конфликт без override_conflicts.
- Перенос между месяцами при смене даты выполняет сам RPC (recalculate_month для обоих месяцев).

## Предварительный расчёт

estimateAccountPay: версия ставок, действующая на дату смены (selectRateVersions), только почасовые интервалы, поминутный обход с учётом дней недели и ночных окон. Нет ставок или полное отсутствие покрытия → NULL → «—»; частичное покрытие → сумма покрытых минут + пометка о непокрытых часах. Фиксированные выплаты, чаевые, процент и премии в оценку не входят. Завершённые смены при изменении ставок не пересчитываются.

## Ограничения для следующих этапов

- Выручка, чаевые, премии/штрафы, фиксированные выплаты и итоговый заработок не подключены: серверная граница отклоняет ненулевые значения до их этапа.
- Статус pending недоступен из интерфейса: в существующем RPC нет операции перехода в pending.
- Корзина личных смен (просмотр/восстановление/очистка) не реализована: shift_restore/shift_purge/trash_clear существуют в RPC, но UI ждёт отдельного этапа.
- Явное подтверждение пересечения (override_conflicts) намеренно недоступно: конфликтующая смена не сохраняется.
