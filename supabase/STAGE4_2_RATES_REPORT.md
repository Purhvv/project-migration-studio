# Shiftly — этап 4.2: личные ставки

## Результат
- Ставки доступны из «Профиль → Мои рабочие места → Ставки» у конкретного места; прежний раздел «Ставки» сохранён.
- Можно задавать произвольное название, почасовую оплату в рублях, время начала/окончания, добавлять и удалять интервалы.
- Отдельно показаны действующая, запланированные и прошлые версии. Будущие версии не выдаются за действующие; дата определяется в часовом поясе места работы.
- Сохранены тема, компоненты и адаптация формы под узкий экран. Предусмотрены пустые состояния, индикатор сохранения и уведомления об ошибках/успехе.

## Сохранение и доступ
Используется существующий путь `accountWrite → shiftly_write`, операция `publish_rates`. Чтение — `getAccountSettings` через отдельные account query options. Новый RPC и таблицы не создавались.

Каждое сохранение публикует новую неизменяемую версию `rate_versions` с интервалами `rate_intervals`. Существующие фиксированные выплаты и ограничения дней недели переносятся без изменений. После успешного сохранения инвалидируется пользовательский кэш и данные повторно читаются из Supabase.

Почасовая оплата передаётся канонической десятичной строкой; сервер использует существующий `money_value` и NUMERIC. Числовые JSON-значения для почасовых ставок отклоняются до RPC. JavaScript не вычисляет оплату смен.

Идентичность проверяется серверной сессией и Auth getUser; `user_id` от клиента не принимается. Прямых INSERT/UPDATE/DELETE из браузера нет. RLS и серверные ограничения базы сохранены.

- Проверены конкретные примеры 250/300/350 ₽, произвольные названия, положительные суммы и два десятичных знака, некорректное время/дата, пустые интервалы, обычные/ночные пересечения, граница недель, соприкасающиеся интервалы и разделение текущих/будущих версий.
- Тест формы подтвердил отправку названия и строки `250.25` через publish_rates, без user_id; конфликт блокирует сохранение, удаление конфликтного интервала возвращает возможность сохранить.
- Автоматическая сборка: `build OK`, последняя проверка после добавления тестов — 2026-11-09 14:29:42 UTC.
- В браузере без сессии `/account` перенаправляет на `/auth?reason=session`; мобильный экран входа проверен.
- Реальное сохранение и чтение после повторного входа НЕ проверены: подключён внешний Supabase, для которого управляемая сессия недоступна. Тест формы использует подмену ответа только внутри теста, не в приложении. Пользовательские тестовые данные в базе не создавались.

## Ограничения
- Перерасчёт завершённых прошлых смен не реализован в существующем серверном контуре: историческая публикация с завершёнными сменами запрещена. В форме этот выбор обозначен как недоступный; защита не обходится. Нужна отдельная согласованная операция предварительного просмотра и подтверждения.
- Можно применить новую версию только с выбранной даты. На дату уже существующей версии публикация запрещена существующей UNIQUE-защитой; требуется другая дата.
- Существующий publish_rates сам пересчитывает предварительную оплату будущих planned-смен по утверждённой SQL-логике. Этот эффект не добавлялся и не менялся; завершённые смены защищены. Смены, календарь, заработок и комиссии на этом этапе не подключались.
- Удаление интервала означает его отсутствие в новой версии, не физическое удаление из прошлой неизменяемой версии.
